Cosmia: Next.js eCommerce template

Documentation for version 1.0.0. Read it top to bottom once; every later section stands alone.

1. Introduction and features

Cosmia is the front end of a skincare and cosmetics shop, built with Next.js (App Router), React and TypeScript. It reads products, categories and blog posts from JSON files and keeps the cart, orders and accounts in the visitor's browser, so it builds and runs anywhere Node runs, with no database and no environment variables. When you are ready for a real shop, you connect your own backend through one interface (section 9).

  • 10 shop layouts (sidebar left or right, list rows, load more, top filter panel, horizontal filters, filter drawer) and 10 product page layouts (default, colour, subscribe and save, sale countdown, two thumbnail layouts, one and two column galleries, inner and external zoom), 5 blog layouts, all listed on one demo page (/demos).
  • Cart drawer and cart page, checkout, order confirmation, order tracking, wishlist, compare, quick view, live search, newsletter popup, accounts (demo), reviews and blog comments (demo).
  • Content pages: About, Contact, FAQs, Store locator, four policy pages, 404 and error screens. A UI kit page (/ui-kit) shows every component and token.
  • Responsive from 320 to 1920 px, with a menu drawer, a filter sheet, a sticky add-to-cart bar and 44 px touch targets on phones and tablets. Tested at 1920, 1440, 1280, 1180, 1024, 768, 390 and 320 px.
  • Accessible: automated checks (axe) report no serious violations including colour contrast; focus is trapped in every dialog and drawer; reduced motion is respected.
  • Design tokens in one CSS file, one settings file to rebrand, typed content with schemas, and more than 400 automated tests (Vitest and Playwright) included.

5. Rebranding

  1. Open src/config/site.ts. Change name, tagline, description, url (your public address), the contact block, the social profile addresses and the shop rules: currency, free-shipping threshold, flat shipping rate, return window, countries.
  2. Logo: the logo is the site name set in the display font, drawn in src/components/layout/Header.tsx, src/components/home/HomeHeader.tsx and the two footers. Replace it with an image or SVG there if you prefer.
  3. Favicon and share image: replace src/app/icon.svg and src/app/favicon.ico; src/app/opengraph-image.tsx draws the share preview from your name and tagline.
  4. Fonts: Instrument Sans, Prata and Allura are installed as npm packages (@fontsource) and imported in src/app/layout.tsx. To change one, install another @fontsource package, change the import and update the three font variables in tokens.css.
  5. Page copy that is not a setting lives in src/content (About, FAQs, policies, stores). Edit the text there.

A unit test (tests/unit/brand-guard.test.ts) fails if the original brand name or demo contact details appear anywhere in src outside site.ts and the data files. After rebranding, if it fails it tells you which file still holds the old text.

6. Theming with design tokens

Every colour, font size, weight and spacing value comes from src/styles/tokens.css. Components use var(--color-primary) and similar names, so changing a token changes the whole site.

Token groupExamples
Text colours--color-dark-01 (main text), --color-dark-02, --color-dark-03 (muted), --color-light-01 (text on dark)
Surfaces--color-bg-body, --color-bg-light-01 (cards), --color-bg-dark
Brand--color-primary (buttons, badges), --color-secondary (links)
Type--font-sans, --font-display, --text-12 to --text-56
Touch size--tap (44 px minimum for controls on phones and tablets)

If you change a colour, check the contrast: text must keep a ratio of at least 4.5 to 1 against its background. npm run e2e includes an automated contrast check across the pages.

Breakpoints

Only three media queries are used, all max-width: 1439px (laptops), 1100px (tablets and below) and 767px (phones). A unit test fails if another width or a min-width query is added, to keep the layout predictable.

Choosing your default layouts

  • Shop: the default is DEFAULT_SHOP_LAYOUT in src/lib/shop-layouts.ts. Visitors can still pass ?layout=.
  • Product: each product has an optional pdpLayout in src/data/products.json; without one the page uses "details-default". ?layout= overrides it for previews.
  • Blog: the default is DEFAULT_BLOG_LAYOUT in src/lib/blog.ts.

The menus are defined in src/config/navigation.ts.

8. Content: the data files

All catalogue and blog content is in src/data/*.json. src/data/schema.ts holds a Zod schema for each file, and a unit test checks that every file matches its schema and that every reference (a product's category, a review's product) points at something that exists. Edit the JSON, then run npm test.

FileHolds
products.jsonProducts: name, slug, description, ingredients, badge, rating, status, layout
variants.jsonSizes of each product: price in integer cents, compare-at price, SKU, size label
inventory.jsonStock per variant
categories.json, product_categories.jsonCategory tree and which product is in which category
colors.json, product_colors.jsonColour swatches and their product links
product_images.json, product_tags.jsonPictures (paths under public/images) and tags
collections.json, collection_products.jsonHome page collections ("Most loved", "Drops")
reviews.jsonApproved product reviews
blog_posts.json, blog_comments.jsonJournal posts (body as a small JSON block list) and comments
banners.jsonHome page banners and the flash-sale countdown

Money is always an integer number of cents (4800 is $48.00). Dates are ISO strings. Sale countdowns use saleEndsInMs / endsInMs (time from now), so the demo never shows an expired sale; use a fixed endsAt date for a real sale.

9. Connecting a real backend

Every page reads data through one interface, DataProvider (src/data/provider.ts). The bundled JsonProvider serves the JSON files. To use your own API (a custom REST service, Shopify Storefront, Medusa, Saleor, a CMS), write another implementation and return it from getProvider() in src/data/index.ts. Pages and components do not change.

Steps

  1. Open src/data/provider.ts. Each method returns the shape the pages need (for example listProducts(query) returns items, totals and page counts).
  2. Create src/data/my-provider.ts that implements DataProvider.
  3. In src/data/index.ts return it from getProvider().
  4. Run npm run typecheck: TypeScript lists every method you have not implemented or shaped correctly.

Example outline

// src/data/my-provider.ts
import type { DataProvider } from "./provider";

export function createApiProvider(baseUrl: string): DataProvider {
  return {
    listProducts(q) {
      // map your API's response to CatalogResult
      // { items, total, page, pageCount, from, to }
      throw new Error("not implemented");
    },
    getProductBySlug(slug) {
      throw new Error("not implemented");
    },
    // ...the other methods of DataProvider
  } as DataProvider;
}

The provider methods are synchronous in the bundled version. A network API is asynchronous: change the interface methods to return Promise<...> and add await in the read functions in src/server and in the pages that call them. TypeScript marks each place. Plan about one working day for a full catalogue, longer for a headless commerce platform with its own cart and checkout.

What stays in the browser until you replace it

Cart, orders, accounts, reviews, comments, contact and newsletter forms live in src/lib/demo-store. The function names (for example submitContact in forms.ts and placeDemoOrder in orders.ts) are the places to call your own API instead.

10. Cart, checkout and accounts in demo mode

  • The cart stores variant ids and quantities in localStorage under the prefix cosmia.demo.. Prices and stock are always re-read from the data, so a changed price shows at once.
  • Checkout validates the form with the same Zod schemas used for the data, then stores an order in the browser and opens the confirmation page. Nothing is charged and nothing is sent. Payment methods shown: bank transfer, cash on delivery, check. To show the demo test card, build with NEXT_PUBLIC_PAYMENT_METHODS=bank_transfer,cod,check,card_test.
  • Accounts (register, login, forgot and reset password) keep a profile and a session in the browser. Passwords are stored as a salted digest for the demo only; this is not real security. Because no email is sent, the forgot-password page shows the reset link on screen.
  • Order tracking finds orders stored in the browser. A sample order is always available: number CSM-DEMO2026 with email demo@example.com.
  • A dismissible "Demo mode" note appears on the login, account and checkout pages. Remove it in src/components/feedback/DemoNotice.tsx when you connect a backend.

11. Images

Pictures live in public/images and are referenced by path in the data files and components. Replace them with your own photographs and keep the file names, or update the paths. The photographs included for the live preview are not part of your licence unless CREDITS.md says so; see section 14.

  • Product pictures: public/images/products, listed in product_images.json.
  • Aspect ratios: product cards 308 × 359, gallery 645 × 752, blog covers 870 × 549, categories square. Other ratios are cropped to fit (object-fit: cover).
  • Keep JPEG or WebP under 300 KB per picture for fast pages.

12. Deployment

HostHow
VercelImport the repository or upload the folder. Framework preset: Next.js. No environment variables are needed. Build command npm run build.
NetlifyUse the Next.js runtime (the default for Next.js sites). Build command npm run build.
Your own Node servernpm ci && npm run build && npm start behind a reverse proxy; set PORT or pass -p.

The shop pages read the query string (filters, sort, layout), so they are rendered per request. A static export (output: "export") is not supported without changing the shop to filter in the browser.

Before you go live, set site.url in src/config/site.ts to your real address: the sitemap, robots.txt and share previews use it. The preview iframe use case works: the site sends no X-Frame-Options header. If you do not want to be embedded, add the header in next.config.ts.

13. Accessibility and browser support

  • Automated tests check every key page with axe, colour contrast included, at desktop, tablet and phone widths. Keyboard tests check the menu drawer, filter sheet, cart drawer and dialogs: Tab stays inside, Escape closes, focus returns.
  • Controls are at least 44 × 44 px on tablets and phones. Motion respects prefers-reduced-motion.
  • Browsers: the current versions of Chrome, Edge, Firefox and Safari. The test suite runs on Chromium, Firefox and WebKit.

16. FAQ and troubleshooting

It does not start: "Node version"

Check node -v. You need 22 or newer.

The port is in use

npm run dev -- -p 3001 starts on another port.

I changed a JSON file and the page did not update

In development the page reloads by itself. After a production npm run build you need to rebuild. If a test now fails, the message names the file and the field.

A price looks wrong

Prices are integer cents. 4800 is $48.00, 480 is $4.80.

The cart or orders disappeared

They live in the browser. Clearing site data, a private window or another browser starts empty. That is expected in demo mode.

Where do I add a page?

Create src/app/(site)/my-page/page.tsx; the (site) group adds the header and footer.

Can I use it with Shopify, WooCommerce or Medusa?

Yes, as a front end: see section 9. The backend integration itself is not included.

The Playwright tests cannot find a browser

Run npx playwright install chromium once (add firefox webkit for the other browsers).

17. Support policy

Support covers questions about how the template works, bugs in the template as delivered, and help with the documented setup. It does not cover installation or deployment on your hosting, customisation or new features, backend integration, third-party services, or problems caused by changes you made.

  • Support period: 6 months from purchase (extendable on the item page).
  • How to ask: use the item's comments or support channel on the marketplace where you bought it, and include your Node version, what you did and any error text.
  • Response target: within 1 to 2 business days (Monday to Friday).
  • Updates: bug fixes and compatibility updates are free for everyone who bought the template; changes are listed in the changelog.
